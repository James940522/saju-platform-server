## 프롬프트 비용 및 개선 후보

실제 Kie 요청 본문은 **28,223 UTF-8 bytes**였다. 아래 수치는 JSON 안의 각 메시지 문자열 크기이며, 전체 요청에는 JSON 키와 이스케이프 비용도 들어간다. 토큰 수는 측정하지 않았다.

| 구성 | 크기 | 내용 |
| --- | ---: | --- |
| 출력 schema 지시 | 1,002 bytes | 결과 JSON 구조 |
| 시스템 프롬프트 | 9,270 bytes | 분석 범위·비교 기준·출력 규칙 |
| 입력 데이터 | 15,465 bytes | 출처·2명의 서버 분석 결과 |

입력 중 두 사람의 `hiddenStemFacts`가 합계 4,509 bytes, `fortuneTellerAnalysis`가 합계 6,278 bytes다. 저장소 전체, 출생정보 원문, 달력 API 원문을 보내는 구조가 아니다. Kie 요청에 검색 도구나 함수 호출도 없고, 출처 URL에 접속하지 않도록 명시한다.

줄일 수 있는 부분은 다음과 같다. 이번 측정에서는 비교 조건을 유지하기 위해 수정하지 않았다.

1. **중복 지시**: 시주를 만들지 말 것, 정보 부족을 감점하지 말 것, 원본 점수를 순위 점수로 쓰지 말 것 등이 여러 위치에서 반복된다. 의미를 보존해 한 번씩 정리할 수 있다.
2. **재물운 관련성이 낮은 부가 설명**: 용신 추천의 색상·방향 등과 참여자별로 반복되는 출처 버전·공통 한계 문구는 입력량을 늘린다. 다음 최적화에서 재물운용 전달 데이터만 선별하거나 공통 메타데이터를 한 곳으로 모으는 후보가 된다. 강약·격국·용신 판단과 실제 원국 근거는 유지해야 한다.
3. **여러 제약을 동시에 만족하는 출력**: 모든 사람의 상대 비교, 실제 근거 ID 선택, 첫째·마지막 사람의 이름 표식, 짧은 제목과 글자 수 조건은 작업을 복잡하게 한다. 다만 누락·허위 근거를 줄이는 목적이 있으므로 시간 단축만을 위해 검증을 제거하지 않는다.
4. **추론 수준은 제공자 기본값**: `reasoningEffort: null`이므로 옵션을 보내지 않는다. 실제 내부 추론량은 현재 로그에서 확인할 수 없다. 품질을 보존하기 위해 임의로 `low`로 바꾸지 않았다.

현재 `stream: false`라 완성 응답을 기다린다. [Kie 공식 문서](https://docs.kie.ai/market/gemini/gemini-3-8-flash-openai)에 스트리밍 방식이 있지만, 적용하려면 SSE 수신·완료 검증이 필요하다. 스트리밍은 중간 수신 상태를 관찰하는 데 도움이 될 수 있으며 전체 처리 시간을 줄인다고 보장하지 않는다.

## 보강한 진단 로그

`kie_request_started`, `kie_request_completed`, `kie_request_failed`에 `timeoutMs`, `promptVersion`, `participantCount`, `requestBytes`, `reasoningEffort`를 남긴다. 응답 헤더 수신 시 `kie_response_headers_received`를 추가했다. 완료·실패 로그에는 `headersAfterMs`, `responseBytes`도 포함한다.

- `httpStatus: null`, `headersAfterMs: null`: 응답 헤더 수신 전 실패.
- `httpStatus: 200`, `headersAfterMs` 존재: 헤더 이후 본문 전송·파싱·완료 형식 단계 확인. 일부 수신했다면 `responseBytes`가 0보다 크다.
- `model_output_schema` 또는 `model_references`: 응답 수신 이후 결과 검증 실패. 네트워크 대기와 구분한다.

성공·진행 상세 로그는 debug 수준이며, 실패 로그에는 위 메타데이터를 함께 남겨 운영의 error 로그만으로도 확인할 수 있다. 키·이름·생년월일시·원국 사실·프롬프트·AI 응답 본문은 기록하지 않는다.
