# 재물운 전용 프롬프트 관리와 5분 실행 예산

2026-09-14. 이번 변경은 재물운 랭킹에만 적용한다. 개인 상세 사주, 전생 관계, 취업 운세의 프롬프트로 재사용하지 않는다.

이 문서는 v8 적용 당시 기록이다. 현재 본문은 버전별 파일로 분리되었으며, 편집 위치와 v8 롤백 방법은 [v9 적용과 롤백](./wealth-ranking-prompt-v9.md)을 참고한다.

## 어디를 수정하나

| 목적 | 파일 / 키 |
| --- | --- |
| 재미, 말투, 비교 기준, 제목 지시 | `src/config/reading-prompts.config.ts` → `readingPrompts['wealth-ranking'].systemPrompt` |
| 저장 결과에 기록하는 프롬프트 버전 | 같은 객체의 `version` (`wealth-ranking-v8`) |
| 모델과 추론 강도 | `src/config/ai-model.config.ts` → `wealthRanking` |
| AI에 보낼 분석 데이터 선택 | `src/modules/readings/infrastructure/wealth-ranking-prompt-input.ts` |
| 모델 출력 검증 | `src/modules/readings/infrastructure/wealth-ranking.prompt.ts` |
| 시간 예산 | `src/config/wealth-ranking-runtime.config.ts`, `.env`의 `WEALTH_RANKING_TIMEOUT_MS` |
| 인증키 | 서버 루트 `.env`의 기존 Kie/KASI 키 |

```ts
const prompt = readingPrompts['wealth-ranking'];
// prompt.systemPrompt를 system 메시지에, prompt.version을 결과에 사용한다.
```

문구를 바꾸면 버전도 올리고 서버를 재시작한다. 운영에서는 빌드 후 재시작한다. 글자 수/필드 요구를 변경하면 모델 출력 schema도 함께 점검한다. 다른 상품이 실제 구현될 때 그 상품의 키와 전용 prompt/output schema를 추가한다.

## 콘텐츠

- 서로 다른 돈 버는 스타일과 돈을 지키는 습관을 생활 속 비유로 풀어 쓴다. 모든 사람에게 같은 조언을 복사하지 않는다.
- 개인 운세는 특징 + 실천 습관을 한 문장으로, 권장 50~90자/최대 140자다.
- 비교는 첫 사람과 마지막 사람 두 명에 집중한다. 권장 200~300자/최대 400자, 3~4문장 한 단락이다. 모델은 `{{pN}}님` 표식을 쓰고 공개 조회 시 서버가 현재 참여자 이름으로 바꾼다.
- 비교 제목은 내용에 맞춰 AI가 만든다. 권장 15~30자/최대 60자다.
- 근거는 실제 ID 1~2개를 선택하며 최소 하나는 원국 근거다. 원국/지장간/삼합의 후보 ID는 모두 전달한다.
- 마지막 순위도 강점과 실천 방향을 제시한다. 동등한 입력에 억지 차이를 만들거나 시간 미상 자체를 감점하지 않는다.

실제 합성 입력 테스트에서 생성된 제목: **결실로 빚어내는 재주와 통 크게 이끄는 추진력**.

## 전달 데이터

저장된 만세력 → KASI 음양력/절기 대조 → 설치된 fortuneteller 분석 → 재물운용 데이터 선택 → Kie 1회 → schema/참여자/근거 검증 → DB 저장 흐름이다. AI로 데이터를 요약하는 중간 호출은 추가하지 않았다.

유지하는 값은 원국 사실, 지장간과 근거 ID, 오행 구성, 십성 가중치, 월령, 지지 관계, 제공된 강약/격국/용신/신살/재물 분석, 개인별 전체·부분 분석 범위 및 경고다. 시간 미상자는 시주가 필요한 함수 결과가 계속 null이며 다른 사람의 4주 분석은 유지한다.

전송에서 제외하는 값은 반복 출처 URL·라이브러리 버전·정책 메타데이터, 겹치는 내부 근거 목록, 랭킹에 사용하지 않는 원본 재물 점수, 용신 추천 색상·방향이다. KASI 대조 상태는 서버 context에 남겨 충돌 차단과 안내문에 사용한다. 공식 데이터를 운세 정확도 인증으로 설명하지 않는다. 라이브러리 분석 문장을 자의적으로 잘라내거나 자체 재물 점수를 새로 만들지 않는다.

같은 합성 입력에 대해 UTF-8 요청 본문을 로컬 비교했다. 마지막 1명은 시간 미상이다. KASI 상태 메타데이터는 양쪽 동일하게 disabled로 두었으며, 실제 네트워크 호출과는 별도의 크기 비교다.

| 인원 | v7 요청 | v8 요청 (`low` 포함) | 감소 |
| --- | ---: | ---: | ---: |
| 2 | 23,913 bytes | 14,614 bytes | 38.9% |
| 3 | 30,906 bytes | 19,728 bytes | 36.2% |
| 5 | 44,857 bytes | 29,862 bytes | 33.4% |

주요 system 프롬프트는 9,270 → 4,724 bytes다. 토큰 수나 추론 시간 감소율을 뜻하지는 않는다.

## 실행 시간과 실패 처리

모델은 `gemini-3-8-flash-openai`를 유지하고 `reasoning_effort: low`를 요청한다. [Kie 공식 문서](https://docs.kie.ai/market/gemini/gemini-3-8-flash-openai)의 추론 옵션을 사용하며, low 값으로 실제 HTTP 200 및 결과 검증을 확인했다. Provider가 내부에서 어떤 추론 예산을 사용했는지는 응답 시간만으로 확인할 수 없다.

```env
WEALTH_RANKING_TIMEOUT_MS=300000
```

- AI 설정: 기본/최대 300초. 실제 호출은 남은 작업 시간에서 저장 여유 5초를 뺀 값으로 제한하므로 최대 약 295초다. 300초보다 큰 기존 환경변수는 시작 검증에서 거절한다.
- 작업 전체: DB `createdAt`부터 300초. 대기·준비·AI·저장이 같은 마감시각을 사용한다. 동기 API는 호출 시작부터 계산한다.
- 준비/대기로 시간이 소진되면 AI 시간도 줄이고, 저장을 위해 5초를 남긴다.
- 시간이 끝나면 실제 Kie fetch에도 취소 신호를 전달한다. 자동 재시도와 임의 결과 생성은 하지 않는다.
- 만료된 작업은 `failed / READING_TIMEOUT`으로 기록하고 lease를 해제한다. 늦은 응답으로 성공 상태를 덮어쓰지 못하게 한다. 트랜잭션 안에서도 마감시각을 재확인한다.
- 워커가 중단되었거나 DB가 응답하지 않으면 300초 시점의 상태 기록까지 보장할 수는 없다. 정상 워커의 만료 점검 간격은 2초이고 화면 갱신도 polling 간격만큼 늦을 수 있다. 이것은 성공 결과의 100% 시간 보장과 구분해야 한다.

로그는 요청 ID, 단계, 입력 bytes, 설정된 제한시간, 응답 헤더 대기시간, 전체 소요시간, 실패 이유만 기록한다. 프로필·프롬프트·원본 응답·키는 운영 로그에 남기지 않는다.

## 실제 호출 검증

실제 사용자와 DB 쓰기 없이 합성 참여자를 사용했다. 모든 사례에서 KASI 음양력/절기 대조는 matched였고, 시간 미상 1명만 부분 분석이었다. 전체 시간은 계산/대조/분석/AI/출력 검증까지이며 DB 대기 및 저장 시간은 포함하지 않는다.

| 조건 | 결과 | 전체 / AI |
| --- | --- | --- |
| 3명, v8, Provider 기본 추론 | 출력 검증 통과 | 8.337초 / 8.219초 |
| 5명, v8, Provider 기본 추론 | 헤더 수신 전 제한시간 초과 | AI 150.015초에 중단 |
| 5명, v8, low 추론 요청 | 출력 검증 통과 | 14.826초 / 14.585초 |

마지막 설정을 적용했지만 소수의 호출만으로 장기 성공률이나 지연의 원인을 확정할 수는 없다. 같은 입력의 기본 설정과 low 설정에서 관찰된 차이이며, Provider의 대기열 변동도 분리 측정하지 못했다.

재검증 명령(호출마다 1회 유료 AI 생성, 서버 빌드 필요):

```bash
npm run check:wealth-ranking -- --with-ai --participants=5 --unknown-time
```

## 호환성과 검증 범위

공개 endpoint/응답 형태와 DB schema는 이번 변경으로 바뀌지 않는다. 기존 결과는 공개 계약의 최대 600자 본문/선택적 제목 정책으로 계속 읽는다. 새로운 AI 출력만 최대 400자로 제한한다. 마이그레이션과 프론트엔드 수정은 필요 없다.

lint, 단위 테스트 252개, e2e 99개, build 통과. 대기 시간 차감, 늦은 KASI 응답의 AI 호출 방지, 실제 취소 신호 전달, 작업 만료 후 늦은 결과 저장 방지를 검증했다.

실제 PostgreSQL 통합 테스트는 별도 임시 스키마 생성 단계에서 계정 권한 오류(42501)로 실행하지 못했다. 새 통합 테스트는 전용 `TEST_DATABASE_URL`로 실행해야 한다. 공유 테이블을 사용하는 모드로 대신 실행하지 않았다.

초기 검증은 Codex의 `41a2/saju-platform-server` 작업 폴더에서 수행했다. 실제 서버 적용과 동일 5명 요청의 후속 진단은 [5분 제한과 지연 개선 점검](./wealth-ranking-latency-options-2026-09-14.md)을 참고한다.
