# 만세력 입력·표시·저장 CRUD 점검

점검일: 2026-09-10

## 결과

로그인된 로컬 클라이언트(`http://localhost:3000/profiles`)와 실행 중인 Nest API, 연결된 개발 PostgreSQL에서 입력 → 미리보기 → 저장 → 조회 → 수정 → 삭제를 확인했다. 점검 범위에서 계산·저장 계약의 불일치는 발견되지 않았다. 입력을 고친 뒤 이전 저장 오류가 남는 UI 문제 1건을 수정했다.

## 실제 브라우저 및 DB 대조

| 항목 | 확인 결과 |
| --- | --- |
| 음력·한국시 보정 | 음력 1965-03-10 07:20 → 양력 1965-04-11, 보정 시각 06:50. 년주 乙巳, 월주 庚辰, 일주 乙未, 시주 己卯로 사용자 레퍼런스와 일치 |
| 표시 | 십성, 일간, 원국 및 보정 정보 정상. 오행 목3·화1·토3·금1·수0, 공망 辰巳. 미리보기의 ‘오행 · 공망 자세히 보기’ 동작, 대운 UI 없음 |
| 저장 전 미리보기 | 입력 변경 시 이전 결과가 사라지고 새 결과로 전환. 미리보기와 실패한 저장 시도는 프로필/차트 행을 만들지 않음 |
| Create / Read | 테스트 프로필 A 생성 후 목록·상세·새로고침 정상. DB 프로필 1개, 차트 1개, 생성 요청 기록 1개 및 대표 지정 확인 |
| 이름만 수정 | 이름 변경 후 차트 ID와 계산 시각 유지, 차트 수 1개 유지 |
| 출생시간 수정 | 정확한 시각 → 시간 미상 변경 시 새로운 차트 생성, 기존 차트 보존. DB 시·분은 NULL, quality는 partial, 시주는 NULL |
| 시간 미상 표시 | 새로고침 후에도 시주 제외 6글자 및 관련 안내 표시. A의 오행은 목2·화1·토2·금1·수0 |
| 원래 입력 복원 | 07:20으로 되돌리면 최초 차트 ID와 계산 시각 재사용. 이력은 2개로 유지 |
| 두 번째 프로필 | 양력 1994-05-22 시간 미상 B 저장·조회. 甲戌 / 己巳 / 戊申, 시주 없음. DB와 UI 모두 6글자 집계 |
| 잘못된 입력 | 양력 2월 30일은 클라이언트에서 차단. 없는 윤달은 서버 미리보기·등록·수정에서 거부하고 안내 표시 |
| 절기 경계 | 양력 2024-02-04 시간 미상 입력 시 출생시간이 필요하다는 서버 안내 표시 |
| 실패한 수정 | 잘못된 윤달로 B 수정 시 기존 생년월일·현재 차트·차트 수가 바뀌지 않음 |
| Delete | 사용자 확인 후 A 삭제: A의 모든 차트 이력 삭제 및 B 대표 승계. B 삭제 후 빈 목록 표시 |
| 삭제 후 조회 | A의 기존 상세 주소로 접근하면 ‘사주 프로필을 찾을 수 없어요’ 표시 |
| 정리 | DB에서 A/B 프로필, 연결 차트, 대표 참조, 생성 요청의 프로필 참조가 모두 0개임을 확인 |

삭제 재시도 방지를 위한 생성 요청 tombstone은 기존 정책에 따라 유지된다. 삭제된 프로필의 생년월일·이름·만세력 JSON은 이 기록에 저장하지 않는다.

## 발견 및 수정한 문제

잘못된 윤달로 저장을 시도한 뒤 정상 날짜로 바꾸면 새 계산 상태와 함께 이전 저장 오류가 남아 있었다.

- 공통 폼에 입력 변경 알림을 추가해 이전 로컬 제출 오류를 지운다.
- 등록·수정 폼은 해당 알림으로 이전 서버 저장 오류를 지운다.
- 이름 지우기 버튼에도 동일하게 적용한다.
- 브라우저에서 오류 발생 후 입력을 수정했을 때 오류가 제거되고 미리보기가 다시 계산되는 것을 확인했다. 수정 API 오류에서도 같은 동작을 재현·검증했다.

변경 파일:

- Frontend `src/features/saju_input/ui/saju_profile_form.tsx`
- Frontend `src/features/saju_input/ui/create_saju_profile_form.tsx`
- Frontend `src/features/saju_input/ui/update_saju_profile_form.tsx`
- Backend `docs/saju-end-to-end-audit.md` (이 기록)

이번 보완은 표시 상태만 변경한다. 공개 API, OpenAPI, DB 스키마, 계산 정책은 변경하지 않아 추가 migration이나 consumer 전환이 필요하지 않다.

## 범위와 후속 사항

요청된 만세력 입력·표시·저장 CRUD 범위에서 차단된 항목이나 추가 migration은 없다. 생산 환경 부하 테스트와 실제 iOS/Android 기기별 검증은 이번 로컬 기능 점검에 포함하지 않았다. 레퍼런스 일치는 공유된 입력 및 고정 테스트 사례를 기준으로 하며 모든 서비스의 모든 계산 정책이 동일하다는 의미는 아니다.

이번 브라우저 점검에서 만든 두 프로필과 차트는 삭제했고, 점검용으로 직접 시작했던 임시 Next 프로세스도 종료했다.
