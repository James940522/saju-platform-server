# 개인정보처리방침 초안 검토 메모

작성 기준일: 2026-09-10. [전문 초안](./privacy-policy-draft.md)은 출시 전 검토 문서다. 현재 구현과 계획 중인 기능을 구분했으며, 실제 배포 환경과 계약을 확인하지 않은 항목은 확정하지 않았다.

## 실제 구현과 대조한 내용

- 현재 클라이언트 로그인 버튼은 카카오만 제공한다. 오래된 인증 안내 문서의 네이버·이메일 가입을 현재 서비스로 옮기지 않았다.
- `User`, `UserConsent`, `SajuProfile`, `SajuChart`, `SajuProfileCreation`, `AccountWithdrawal`의 실제 저장 항목을 반영했다. 프로필 삭제 뒤에도 중복 방지 식별정보·요약값이 남는 점과 회원 탈퇴 시 삭제되는 점을 구분했다. 요약값도 개인정보 판단에서 자동으로 제외하지 않는다.
- 앱의 `users` 테이블에 이메일·프로필 이미지가 없다는 사실만으로 인증 서비스가 이를 전혀 받지 않는다고 쓰지 않았다. 카카오 동의항목과 Supabase 인증 메타데이터는 별도 확인해야 한다.
- 로그인으로 만든 인증 계정과 서비스 가입 완료를 구분한다. 만 14세 확인 전에도 인증 서비스 계정·세션이 생성될 수 있다. 미완료 가입·연령 미충족 계정의 정리 주기와 고지는 운영 적용 전 확정해야 한다.
- 사주 프로필 삭제는 실제 삭제 및 차트의 연쇄 삭제로 처리된다. 만세력 미리보기는 계산 응답을 반환하며 저장된 프로필 생성과 다르다.
- 현재 탈퇴 구현은 프로필·동의 이력 제거 후 카카오 연결 해제, Supabase 계정 삭제, 앱 계정·임시 탈퇴 작업 삭제 순서다. 외부 연동 실패 시 재시도하므로 모든 정보가 즉시 삭제된다는 약속을 하지 않았다. 기능 활성화·배포 여부와 장기 실패 정리 기준은 별도 확인한다.
- 결제·AI·기도초·고객센터 자료는 관련 기능 도입 전에 확정할 항목으로 구분했다. 참고 서비스의 귀인지도, Gmail 자동처리, Resend, 고정된 OpenAI 보유조건 및 GA4 추적 설정을 가져오지 않았다.
- 글꼴은 현재 패키지에서 제공되므로 Google Fonts로 접속정보를 전송한다고 쓰지 않았다. AWS·Vercel은 제품의 배포 계획과 실제 위탁 현황을 구분해야 한다.

## 게시 전 확정할 항목

1. 개인정보 보호책임자 또는 담당부서, 실제 권리행사 접수 전화·이메일, 시행일. 대표자 최재영을 보호책임자로 자동 지정하지 않았다.
2. 회원가입·사주 입력별 필수/선택 항목과 법적 근거, 동의 안내. 개인정보처리방침 확인과 필요한 수집·이용 동의를 구분하고, 현재의 `privacyPolicyAccepted: true`가 모든 개인정보 처리 동의를 대신한다고 해석하지 않는다. 이번 작업은 해당 API를 변경하지 않는다.
3. 카카오 실제 동의 범위와 인증 서비스에 저장되는 프로필·세션 항목, 만 14세 확인 전 인증정보 및 가입 미완료 계정의 보유·파기 기준.
4. 수탁업체의 계약상 법인명, 업무·재위탁 현황, Supabase 실제 프로젝트 리전, 백업·로그·지원 접근 국가, 연락처 및 보유기간. 미국 사업자라는 이유만으로 전부 미국에 보관된다고 쓰지 않았다.
5. 개인정보 보호법 제28조의8에 따른 국외 이전 근거와 고지·동의 방법, 거부 절차 및 실제 효과. 현재 페이지의 미확정 표시는 법정 고지 완료를 의미하지 않는다.
6. 접속·인증·보안 로그, 백업, 탈퇴 장기 미완료 건, 일반 문의·첨부자료의 구체적 보유기간과 파기 자동화. 참고 문서의 30일·7일·24시간 값을 그대로 채택하지 않았다.
7. 추가 서비스에서 처리할 정보, PG·AI·기도 수행자·고객문의 도구, 정보 공개 범위 및 필요한 별도 동의. 제3자 사주 정보와 만 14세 미만 대상자 정보의 입력에도 적법한 처리 근거를 확인한다.
8. 최종 전문을 서버의 `CURRENT_PRIVACY_POLICY_VERSION`과 맞추고 기존 동의 기록을 보존한다. 초안을 과거 동의 문서로 소급 적용하지 않는다.

- 국외 이전 근거 및 안내사항: [개인정보 보호법 제28조의8](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=08&joNo=0028&lsiSeq=270351&urlMode=lsScJoRltInfoR).
- 거래기록 6개월·5년·3년 보존 및 분리 보존: [전자상거래법 시행령 제6조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lspttninfSeq=63460). 실제 기록이 발생하고 보존 의무가 적용될 때의 기준이다.
- 수탁업체 명칭 및 고객 데이터 처리 역할 확인: [Supabase 개인정보 안내](https://supabase.com/privacy). 회사의 이용자 데이터에는 실제 계약과 DPA·운영 설정을 추가 확인해야 한다.
- 구제기관 연락처 확인: [개인정보 포털](https://m.privacy.go.kr/front/main/main.do).

## 구현 범위

클라이언트 `/privacy` 페이지, 가입 동의 화면의 두 전문 링크와 돌아오기 흐름, 홈 하단 링크를 추가한다. 회사 정보는 클라이언트 공통 설정을 사용한다. 서버의 API, 동의 버전, 데이터베이스 및 다른 작업의 탈퇴 구현은 변경하지 않는다. 본문은 `../saju-platform/src/domains/privacy/config/privacy_content.ts`와 함께 갱신한다.

## 검증 결과

- 클라이언트 `pnpm lint`, `pnpm build --webpack` 통과. 이전 작업에서 확인한 Turbopack의 환경상 포트 제한을 피하기 위해 프로젝트 설정을 바꾸지 않고 Webpack 옵션으로 빌드했다.
- 로컬 `/privacy` HTTP 200 확인. `/terms`, `/privacy` 모두 빌드의 정상 라우트 목록에 포함된다.
- 14개 항목과 문서·표시 데이터의 내용 일치, 공통 사업자 정보, 타사 고유정보 제거를 확인했다.
- 돌아갈 경로에서 외부 URL·프로토콜 상대 URL·역슬래시 URL·스크립트 URL을 거부하고, 내부 경로의 검색 조건과 해시를 보존하는 검증을 통과했다.
- 전문 열람은 체크박스와 분리된 링크로 처리한다. 두 전문에서 가입 창을 숨기며, 돌아왔을 때 루트 레이아웃에 유지된 동의·연령 선택을 이어 사용한다. 새로고침 또는 새 탭의 선택 복구를 제공하는 것은 아니다.
- 로그인한 상태에서의 브라우저 클릭·시각 검사는 수행하지 않았다. 서버는 문서만 추가했으므로 서버 lint·unit/e2e test·build 및 migration은 실행하지 않았다.
