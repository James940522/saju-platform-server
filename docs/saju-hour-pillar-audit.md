# 한국시 보정 정책과 시주 불일치 수정

2026-09-10. 사용자가 제공한 레퍼런스의 한국시 보정 안내와 07:20 응답을 기준으로,
서비스 기본 계산 정책을 `kr-mean-solar-midnight-v2`로 변경했다.
보정 기준은 서비스의 명시적 규칙이며 모든 사주 서비스의 보편적 표준이라고 단정하지 않는다.

## 확인한 원인과 결과

기존 `kr-kst-midnight-v1`은 `trueSolarTime`을 지정하지 않아 한국시 보정이 없었다.
클라이언트는 선택한 시각을 그대로 전송했고 서버 결과를 표시했다.
원인은 UI 표시나 음양력 변환이 아니라 서버의 시간 판정 기준이었다.

입력: 음력 평달 1965-03-10, 여성, 07:20. 양력 변환: 1965-04-11.

| 항목 | 기존 보정 없음 | 한국시 보정 적용 | 레퍼런스 |
| --- | --- | --- | --- |
| 계산 시각 | 07:20 | 06:50 | 보정 켜짐 |
| 연·월·일주 | 을사·경진·을미 | 을사·경진·을미 | 동일 |
| 시주 | 경진(庚辰) | 기묘(己卯) | 기묘 |
| 시주 천간/지지 대표 십성 | 정관/정재 | 편재/비견 | 편재/비견 |
| 목·화·토·금·수 | 2·1·3·2·0 | 3·1·3·1·0 | 3·1·3·1·0 |
| 대운 시작 | 8세 | 8세 | 8세 |

보정 후 대운 첫 9개 간지와 시작 나이도 신사 8세부터 기축 88세까지 일치한다.
07:00 입력도 기묘다. 한국시 보정에서는 기록 시각 07:29까지 기묘, 07:30부터 경진이다.
균시차까지 켜면 이 날짜의 07:30도 기묘가 되므로 두 방식을 구분한다.

## 확정한 계산 규칙

- 기준 경도 127.5°, 균시차 제외. 사용자의 실제 출생지를 추정한 좌표가 아니다.
- 원본 기록 시각을 `Asia/Seoul`의 당시 표준시·서머타임으로 UTC 순간에 대응시킨다.
- 한국 평균 태양시 = UTC 순간 + 510분. 일반적인 UTC+9 기간에는 30분을 뺀다.
- UTC+8:30 기간은 0분, 그 기간의 서머타임 UTC+9:30은 60분,
  UTC+9 기간의 서머타임 UTC+10은 90분을 뺀다.
- 연주·월주는 실제 UTC 순간으로 절기를 판정한다. 일주·시주는 보정 시각과 `midnight` 규칙으로 계산한다.
- 음력은 양력으로 변환한 뒤 시간 보정을 한다. 원본 음력 날짜나 입력 시각을 덮어쓰지 않는다.
- 클라이언트에는 보정 적용 여부 선택을 추가하지 않고 기본 정책으로 안내한다.

서버는 Node 내장 IANA 시간대 데이터를 사용한다. 별도 API·패키지가 필요하지 않다.
해석한 UTC 순간을 라이브러리가 기대하는 KST로 정규화한 뒤
`trueSolarTime: { longitude: 127.5, applyEquationOfTime: false, applyHistoricalDst: false }`를 전달한다.
역사적 시각 변환을 서버에서 수행했으므로 라이브러리의 역사적 보정은 중복 적용하지 않는다.
단순히 입력에서 30분을 빼서 라이브러리에 전달하면 절기 판정 순간도 달라지므로 사용하지 않는다.

시간대 자료 버전은 `calculation.timeZoneDatabaseVersion`과 입력 해시에 포함한다.
Node/ICU 업데이트로 시간대 자료가 바뀌면 새 계산의 재현성 식별에도 반영된다.

## 경계와 불확실성

- 2024-08-01 00:20은 보정 후 2024-07-31 23:50이다. 날짜 이동은 서버가 계산한다.
- 현재 UTC+9 기간에는 00:29까지 전날 일주, 00:30부터 당일 일주다.
- 시간 미상은 입력 날짜의 대표 일주를 표시한다. 시주·대운 및 실제 보정 날짜·시각은 null이다.
  보정된 자정 전후 출생이면 일주가 달라질 수 있다는 `day_boundary_uncertain` 안내를 반환한다.
- 시간 미상의 월 절입일은 기존처럼 `BIRTH_TIME_REQUIRED_ON_BOUNDARY_DATE` 오류를 반환한다.
  보정된 00:00/23:59의 일주를 비교해 일반 날짜까지 거부하지 않는다.
- 서머타임/표준시 전환으로 존재하지 않는 시각은 `NONEXISTENT_BIRTH_TIME`,
  두 번 존재하는 시각은 `AMBIGUOUS_BIRTH_TIME`으로 400을 반환한다. 임의 선택하지 않는다.
- 1908-04-01 이전에는 라이브러리의 기존 UTC+9 가정을 유지하되 `partial`과
  `historical_time_assumed`로 명시한다. 해외·출생지별 진태양시를 지원한다는 의미가 아니다.

## 응답·저장·화면

`normalizedBirth.time`과 `inputDate`는 기록 원본이다.
`normalizedBirth.timeCorrection`에는 방식, 기준 경도, 균시차 미적용, 당시 UTC 오프셋,
보정 분, 보정된 양력 날짜·시각을 반환한다. 클라이언트는 숫자를 다시 계산하지 않고 표시한다.

Snapshot schemaVersion은 1을 유지하고 새 필드는 optional로 추가해 과거 JSON도 읽을 수 있다.
신규 계산은 새 policyVersion과 보정 메타데이터를 항상 반환한다.
이전 차트는 덮어쓰거나 조회 중 변경하지 않는다. 출생 정보가 포함된 저장 요청에서 이전 계산 정책이
확인되면 새 불변 차트를 만들거나 재사용해 활성화한다. 이름·관계만 보내는 PATCH는 재계산하지 않는다.
DB schema/migration은 변경하지 않는다. 배포 시 Frontend의 보정 표시 지원도 함께 반영해야 한다.

## 검증 범위

실제 서버 계산기와 HTTP 계약 테스트에 원국·십성·오행·대운 비교를 고정했다.
07:29/07:30, 보정 자정과 전월 이동, 시간 미상, 입춘 전후,
역사적 표준시·서머타임 및 전환 시각 오류, 과거 JSON 호환성과 새 차트 활성화를 검증한다.

레퍼런스의 지장간 전체·12운성·납음·합충형파·신살·신강약·격국·용신은 이번 변경 대상이 아니다.
시간 미상 대운도 레퍼런스의 대체 시각·규칙이 확인되지 않아 미제공 정책을 유지한다.
단일 사례 일치로 모든 날짜와 모든 분석 항목이 레퍼런스와 같다고 단정하지 않는다.

## 완료 확인

- Backend: lint, 단위 테스트 65개, HTTP e2e 33개, build 통과.
- Frontend: lint 통과. 일반 `pnpm build`는 샌드박스의 Turbopack 포트 생성 제한으로 실패했고,
  허용된 환경에서 동일 Next CLI의 프로덕션 빌드·타입 검사·페이지 생성을 통과했다.
- 실행 중인 로컬 개발 화면에서 음력 1965-03-10 07:20 → 06:50 → 기묘 표시를 확인했다.
  시간 미상 전환 시 기존 시주 제거·부분 명식·경계 안내, 2024-08-01 00:20 →
  2024-07-31 23:50 날짜 이동 표시도 확인했다.
- 실제 DB 데이터 변경이나 migration을 실행하지 않았다. 과거 저장본 업그레이드는 service test로 검증했다.
